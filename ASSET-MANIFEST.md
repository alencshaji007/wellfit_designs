# Asset manifest

Every asset shipped with the site is listed here, with its provenance. Provenance falls into three types:

- **Client-supplied**: the logo, plus project photographs extracted from the company profile PDF.
- **Original render**: created for this project with the procedural Blender scripts in `tools/renders/`.
- **Open-licence font**: the self-hosted fonts.

Nothing was downloaded from stock libraries or generated by an image AI service.
No asset is presented as something it is not:

- Every render carries an on-image "Illustrative render" label, or a group label for the material studies.
- The footer of every page explains that illustrative renders are not photographs of completed client projects.

## Images — `assets/images/`

Every image is delivered as **AVIF and WebP** at several widths (`name-<width>.avif|webp`). The pages serve them through
`<picture>`/`srcset`, with intrinsic `width`/`height` attributes and lazy loading below the fold; the hero is preloaded with `fetchpriority="high"`.

## Reproducing or extending the renders

The render tools need **Blender 5.2** as a Python module (`pip install bpy==5.2.2`, Python 3.13).

```bash
python3 tools/renders/make_plan.py tools/renders/plan.png      # texture used by the design-desk scene
python -I tools/renders/scenes.py interior-villa-kitchen out.png 0.9 40   # scene, output, scale, samples
python3 tools/renders/optimize.py out.png assets/images/interiors interior-villa-kitchen
```

`scenes.py` lists every scene. Each is around 3–7 minutes on a 4-core CPU at the shipped sizes.
To use AI-generated or commissioned imagery instead:

1. Keep the same file base names and aspect ratios: 16:9 hero and exterior, 3:2 interiors, 4:5 portraits, 1:1 materials.
2. Run them through `optimize.py`.
3. Record their provenance in this manifest. AI images remain illustrative and must keep the "Illustrative render" label (or a similar one) and must never be attached to a client project.
